# botmaker-catalog

The list of published BotMaker bots and plugins. **Checked by a machine, merged by a machine — never a security
claim.**

A bot is a Java program and a plugin runs inside Studio's own process. Every check this repository runs asks
whether an entry *works* and whether its author *controls* the repository it names. None of them asks whether
the code is *safe*, and none of them could. Run a bot or a plugin the way you would run any other program
somebody wrote. Studio shows each entry's rank (admin, trusted, community) and asks before it first loads a
community plugin on a computer.

## Publishing

```bash
botmaker bot publish --repo me/my-bot          # a release, then the pull request adding bots/me__my-bot.json
botmaker plugin publish --repo me/my-plugin    # the checks, then the pull request adding plugins/<id>.json
botmaker bot unpublish me/my-bot               # the pull request removing the entry
botmaker plugin unpublish --id <id>
```

Studio's Publish does the same for a bot. Each command runs this repository's checks on your machine first, opens
one pull request changing one file, and the pull request is **merged automatically** when the same checks pass
here. Install the CLI from [botmaker-cli](https://github.com/BotMakerDev/botmaker-cli).

## Layout

```
bots/<owner>__<repo>.json   { "repo": "owner/name", "tag": "v1.2.0" }, optionally "detached": true
plugins/<id>.json           { "id": "com.x.y", "repo": "owner/name", "tag": "v0.3.0" }
publishers.json             ranks, by GitHub account id; edited by an admin only
catalog.json                GENERATED by index.yml; the only file Studio reads. Never edit it
tools/                      botmaker-cli.version (the pinned check), resolve-cli.sh, entry-facts.sh
```

An entry holds only what its author decides: which repository, which release. Everything else in `catalog.json`
(name, description, topics, stars, the fork's parent, a plugin's contract version, a bot's plugins) is read from
GitHub and from the pom at that tag, as data, by `index.yml`.

A plugin's file is named by its id, so git keeps one file — one owner — per id. A bot's file joins owner and
repository with `__`, since a GitHub login holds no underscore.

## The check

`validate.yml` resolves `com.github.BotMakerDev:botmaker-cli` at the release `tools/botmaker-cli.version` names
and runs `com.botmaker.cli.catalog.EntryGate`. A pull request passes when:

1. it changes exactly one entry file, added, changed or removed;
2. the file's name is what its content names, and the JSON is the schema above;
3. its author made the GitHub Release at `tag` (or, for a release made by an Action, owns the repository);
4. an existing entry changes or goes only by whoever controls the repository the catalog holds today;
5. `tag` is a published release, not a draft or a prerelease;

and, for a bot, its pom at `tag` declares a catalog plugin at a released version, it compiles, and it has a
`main`; for a plugin, `botmaker plugin validate`'s checks pass, the jar's id is the entry's `id`, and JitPack
serves the coordinate at `tag`.

## Ranks

`publishers.json` lists GitHub account ids (users or organisations) as `admin` or `trusted`; everyone else is
community. An entry takes its repository's current owner's rank, so a fork is its owner's and a transferred
repository takes the new owner's. A pull request touching `publishers.json` is never merged automatically.
